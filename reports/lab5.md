# 实验五：并发、同步与死锁检测

## 练习内容

实现 enable_deadlock_detect，在线程申请互斥锁或信号量资源时检查死锁，检测到死锁则返回 -0xdead，并保持资源与等待队列不变。支持开启、关闭，拒绝 0/1 以外的参数。

## 实现

每个进程维护独立 DeadlockDetector，记录各资源可用数量 Available、各线程已持有资源 Allocation 和当前未满足请求 Request。请求时先暂记 Request，再使用消除算法：从 Available 复制 Work，反复找到 Request 不超过 Work 的未完成线程，将其持有的 Allocation 加回 Work；若最终仍有线程不能完成，则回滚这次 Request 并返回失败。这里检查的是实际资源请求，不要求线程预先声明最大需求。

同步原语本身接入记账，因此通过条件变量释放和重新申请互斥锁也会更新状态。阻塞锁和信号量在 unlock/up 时按 FIFO 将资源直接记到被唤醒线程，避免它尚未运行时被误记为空闲资源。自旋锁在真正获得锁时完成等待请求，保留其竞争语义。进程的独占借用均在上下文切换前释放。关闭检测时仍然维护计数，重新开启后能继续使用准确状态。

补齐分页下 get_time、mmap 和 munmap，并固定镜像打包工具依赖，以支持官方同步测试正常运行。

## 验证与原理

官方测试覆盖重复获取同一互斥锁、多资源信号量循环等待、可以正常完成的信号量请求、线程创建、互斥计数器、生产者消费者、哲学家就餐、条件变量和管道等。死锁检测只判断当前等待状态，不预测尚未发生的申请；拒绝危险请求后，调用者可以释放已有资源并恢复执行。

本地验证结果：官方检查器 25/25，lab1 至 lab5 报告检查通过，命令退出码为 0。另以 Rust 主机测试验证请求回滚、两线程资源环、可完成的多实例资源请求、自旋锁实际交接和开关状态，5/5 通过。exec 同时重置检测器及同步对象，防止旧资源编号泄漏到新程序。
