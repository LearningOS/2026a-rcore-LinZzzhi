# 实验一：多道程序与分时多任务

## 练习内容

在 ch3 实现 `sys_trace(request, id, data)`：读取一个用户字节、写入一个用户字节、查询当前任务某个系统调用的累计次数。调用次数应按任务隔离，并包含正在执行的 trace 调用。

## 实现

在任务模块中使用静态二维数组，为每个任务保存 512 项系统调用计数，初始化为零。静态存储避免任务管理器初始化时在启动栈上复制大型数组，防止栈越界破坏只读数据。系统调用统一入口在分派之前调用 `record_syscall`，只更新当前任务的计数，随后释放任务管理器的独占借用，保证 yield 和 exit 可以正常调度。

`request=0` 使用 volatile 读取得到指定地址的字节；`request=1` 将 data 的低八位写入地址并返回 0；`request=2` 查询当前任务的计数。未知 request 或超出计数数组范围的编号返回 -1。ch3 尚未启用分页，地址直接对应用户程序使用的地址；ch4 再增加页表转换和权限检查。

## 验证

使用课程固定版本的官方 Checker 和 Test，运行 `make -C ci-user test CHAPTER=3`，检查时间、休眠、多任务切换、trace 字节读写和系统调用统计。执行结果另记录在根目录本地汇总报告。

## 原理

时钟中断提供抢占时机，yield 提供主动让出 CPU 的入口。任务上下文保存被调用者保存寄存器；陷阱上下文保存用户态寄存器和返回位置。计数属于任务状态，不能作为所有应用共享的全局累计值。

本地验证结果：官方检查器 7/7，lab1 报告检查通过，命令退出码为 0。
